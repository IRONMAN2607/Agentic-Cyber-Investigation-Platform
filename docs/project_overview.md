  ### 1. Problem Statement

  Modern Security Operations Centers (SOCs) face severe alert fatigue, massive log volumes, and human analyst
  shortages. While Large Language Models (LLMs) offer promising speed in synthesizing security telemetry and drafting
  incident summaries, deploying unconstrained LLMs in Digital Forensics and Incident Response (DFIR) introduces
  critical vulnerabilities:

  1. Indistinguishable Fabrications (Hallucinations):
      • In a cyber investigation, a fabricated detail is not merely wrong—it is indistinguishable from a legitimate
      finding. An LLM asserting that an attacker pivoted using CVE-2021-4034 or connecting to a malicious IP carries
      the same syntax, confidence, and authority as an accurate finding.
      • Human responders have no local signal to separate truth from hallucination without exhaustive manual
      verification, risking misdirected incident containment.
  2. Failure of Behavioral Mitigations:
      • Traditional mitigations (Chain-of-Thought prompting, system prompts like "only cite real evidence", RAG, or
      self-critique) rely purely on behavioral compliance. They encourage the model to be honest, but do not make
      ungrounded assertions structurally impossible. Under prompt injection, context exhaustion, or token ambiguity,
      hallucinations still persist.
  3. Lack of Non-Repudiable Forensic Provenance:
      • Forensic investigations require a strict chain of custody. Standard LLM agents produce free-form text that
      cannot mechanically prove which tool run, byte offset, or log artifact generated a specific claim.
  4. Inflation in Security Evaluations:
      • Standard LLM benchmark evaluations often use greedy or multi-claim matching where vague statements (e.g.,
      "suspicious activity occurred") are credited against specific attack steps, inflating perceived model accuracy.

  ### 2. Proposed Solution

  AACIP resolves this through Architecturally Enforced Evidence Grounding governed by a fundamental axiom:

  │ "Deterministic tools produce evidence. LLMs reason over evidence. An LLM is never the unquestioned source of
  │ truth."

  Rather than asking LLMs to be honest via prompt engineering, AACIP enforces evidence grounding at the database
  persistence boundary via machine-checked invariants:

  • Epistemic Assertion Taxonomy: Every finding is strictly classified into:
      • FACT: Directly observed by a deterministic tool. An LLM cannot produce a FACT by construction.
      • INFERENCE: Derived through reasoning over one or more facts; requires cited evidence and explicit natural
      language rationale.
      • HYPOTHESIS: Candidate explanations for anomalies; strictly enforces Popperian falsifiability by requiring
      explicit refutation conditions.
      • UNKNOWN: Explicitly tracks investigative gaps; mathematically capped at INFO severity to prevent false alarm
      escalations.
  • Formal Grounding Invariants (G0–G4, G7):
      • G0 (Non-Bypassability): No finding enters persistent storage without passing validation.
      • G1 (Factual Grounding): A FACT must cite verified deterministic evidence with an immutable tool_run_id.
      • G2 (Inferential Grounding): An INFERENCE must cite evidence and provide non-empty reasoning.
      • G3 (Falsifiability): A HYPOTHESIS is rejected at write-time unless it defines a valid refutation_condition.
      • G4 (Epistemic Humility): UNKNOWN claims cannot exceed INFO severity.
      • G7 (MITRE ATT&CK Bounds): Techniques must map to a verified static catalog generated by deterministic rules,
      preventing hallucinated ATT&CK IDs.
  • Evidence-Backed Graph DAG: Every graph edge connecting entities (IPs, Hosts, Users, Files, Hashes) retains a
  mandatory foreign key to an immutable evidence_id.
  • Adversarial Validation Cycles: A HypothesisAgent formulates competing theories while a ValidationAgent actively
  searches for refuting evidence in bounded loops (MAX_CYCLES = 3).
  • Maximum Bipartite Cardinality Matching: Employs bipartite matching (Hopcroft-Karp / augmenting-path search) to
  benchmark system performance against ground truth without recall inflation.

  ### 3. Technology Used

  #### Backend & Core Engine

  • Language & Runtime: Python 3.12+ (leveraging modern typing, StrEnum, pattern matching).
  • API Framework: FastAPI with Uvicorn (ASGI async web server).
  • Data Contracts & Validation: Pydantic v2 & pydantic-settings (typed schemas for tool arguments, agents, and API
  boundary validation; zero raw shell inputs).
  • Database & ORM: SQLAlchemy 2 (Async ORM with mapper-level append-only mutation blocks) and Alembic for migrations.
      • Development: SQLite via aiosqlite.
      • Production: PostgreSQL via asyncpg (JSONB storage, recursive CTE graph queries).
  • Security & Auth: argon2-cffi (password hashing), PyJWT (role-based access control), SHA-256 content hashing,
  anti-SSRF validators, and magic-byte artifact intake.

  #### Tool Execution & Sandboxing

  • Sandbox Tiers:
      • T0_IN_PROCESS: Pure-Python deterministic log and artifact parsers (auth_log_parser, web_log_parser,
      ioc_extractor).
      • T1_SUBPROCESS: Isolated execution without network, strict resource limits (rlimits, timeouts), strictly
      avoiding shell=True.
      • T2_CONTAINER: Ephemeral containers for untrusted malware/samples.
      • T3_NETWORK: Audited, rate-limited network access for threat intelligence lookups.


  #### Model Abstraction Layer

  • Model Router & Providers: Provider-agnostic llm interface supporting OpenAI-compatible APIs, NVIDIA NIM (Nemotron,
  DeepSeek R1), and deterministic test ReplayProvider with automated circuit-breakers and quota fallback.

  #### Frontend Workspace

  • Interactive Dashboard: Modern responsive web application served by FastAPI static mount ():
      • SVG-based interactive Evidence Graph canvas (drag, zoom, entity inspection).
      • Correlated Forensic Timeline displaying canonical timestamps (observed_at vs collected_at).
      • Competing Hypotheses & Validation tracker.
      • Real-time streaming via Server-Sent Events (SSE) with polling fallback.
      • Capabilities and Limitations disclosure modal dynamically synced with limitations.py.


  #### Testing & Quality Assurance

  • pytest, pytest-asyncio, and httpx driving ASGI in-process tests.
  • ruff (linter/formatter) and mypy (strict static type checker) with 0 errors across 144 files.

  #### Step-by-Step System Working

  1. Artifact Ingestion & Sanitization:
      • An analyst uploads target artifacts (e.g., Linux auth.log, Nginx access logs, PCAP, IOCs).
      • Artifacts are validated via magic bytes, content-addressed via cryptographic SHA-256 hashes, and stored non-
      executable in isolated storage.
  2. Orchestration & Dynamic Planning:
      • OrchestratorAgent boots an InvestigationState lifecycle.
      • A Planner evaluates the artifact metadata and available capabilities in AgentRegistry, emitting a structured
      sequence of tasks with mandatory audit rationales.
  3. Deterministic Tool Execution:
      • Scheduled tool adapters run inside appropriate sandboxes (e.g., T0_IN_PROCESS or T1_SUBPROCESS).
      • Parsers extract normalized events and canonical entity references (canonicalizing IP addresses, lowercasing
      domain names, etc.).
      • The tool generates an uncommitted EvidenceDraft containing source metadata and an execution receipt
      (tool_run_id).
  4. Evidence Store Ingestion & Grounding Verification:
      • The draft enters EvidenceStore.
      • Content hashing ensures deterministic deduplication.
      • If an agent attempts to record a claim:
          • If marked FACT without an authentic tool_run_id, a GroundingError is raised immediately.
          • If marked INFERENCE, supporting evidence citations and explicit rationale are validated.
          • If marked UNKNOWN, its severity is clamped to INFO.

  5. Entity Resolution & Graph Correlation:
      • The CorrelationAgent links extracted entities into the Evidence Graph DAG (entities and entity_edges).
      • Each relational edge (e.g., USER -[AUTHENTICATED_TO]-> HOST) is bound to a verified evidence_id.
      • The ReasoningAgent executes depth-bounded, cycle-safe graph traversals (max_depth = 5) to synthesize multi-
      hop attack paths spanning multiple log sources.
  6. Hypothesis Formulation & Adversarial Validation:
      • The HypothesisAgent analyzes graph anomalies and proposes competing hypotheses (e.g., brute-force attack vs.
      misconfigured automated script).
      • Every hypothesis must explicitly declare refutation conditions (Invariant G3).
      • The ValidationAgent inspects newly extracted evidence against these refutation criteria in bounded cycles
      (MAX_CYCLES = 3), discarding falsified explanations.
  7. Deterministic Risk Scoring & Report Synthesis:
      • risk.py calculates an overall investigation risk score deterministically from verified findings (with a 50%
      discount on unproven hypotheses; LLMs cannot arbitrarily escalate scores).
      • The ReportingAgent renders a comprehensive forensic report that strictly delineates what was observed, what
      was inferred, and what remains unknown.
      • Every claim in the report resolves in one click to raw byte offsets on disk via GET
      /investigations/{id}/evidence/{evidence_id}/provenance, streamed in real-time to the web dashboard.
